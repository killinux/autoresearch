强化学习 · 四连例图解

RL by Example配套 autoresearch中文 / 可视化

从最简单的老虎机，到教小 GPT 做 RLHF —— 一条由浅入深、每步只多学一个概念的路。

一、所有强化学习都是这一个循环

不管多复杂的 RL 算法，骨架都是：智能体做动作 → 环境给反馈 → 智能体据此变得更好。

智能体 Agent
看到状态，决定做什么
（要学习的就是它）
───▶
动作 action
状态 state + 奖励 reward
◀───
环境 Environment
世界的规则（老虎机/迷宫/
倒立摆/打分函数）

智能体不断试探，环境用奖励告诉它"这步做得好不好"， 目标是让长期累计奖励最大。
永恒的矛盾：探索（试没试过的）vs 利用（用已知最好的）。

二、四个例子，一层层加概念

每个例子都在前一个基础上，只多引入一个新东西。这样学最不容易懵。

01

多臂老虎机新增：探索 vs 利用

01_bandit.py

K 台老虎机，每台吐钱水平不同且未知。没有"状态"，每步处境都一样，你只需决定拉哪条臂。这是 RL 最干净的形态，专讲那条永恒矛盾。

核心：价值估计 Q[a] 用增量平均更新 · ε-greedy 偶尔随机探索 · UCB"乐观对待没试过的臂"
会看到：贪心 ~34% < ε-greedy ~81% < UCB ~86%（选中最优臂的比例）—— 只利用会被困住。
02

GridWorld 走迷宫新增：状态 & Q 表

02_qlearning_gridworld.py

加入状态：你站在不同格子，该做的事不同。这就是完整的马尔可夫决策过程(MDP)，用最经典的表格 Q-learning 解。

核心：Q[状态,动作] 二维表 · TD 更新（见下方公式）· 折扣 γ、学习率 α
会看到：前期乱走掉坑（平均 −17 分），学好后稳走最短路（+2 分），并打印一张箭头策略图。
03

CartPole 倒立摆新增：神经网络 + 策略梯度

03_cartpole_reinforce.py

状态是 4 个连续实数，没法做表格 → 用神经网络当函数。而且换思路：不学价值，直接学策略（输出动作概率），这叫策略梯度，最基础版是 REINFORCE。

核心：玩完一整局看回报，好就提高这局做过动作的概率 · loss = −Σ logπ(a|s)·G
会看到：杆子坚持步数从 ~40 涨到几百（REINFORCE 方差大、曲线会抖，正常）。物理引擎自己实现，不依赖 gymnasium。
04

小 GPT 做 GRPO新增：在语言模型上做 RL

04_grpo_tiny_llm.py

把 RL 搬到语言模型上 —— 这正是 ChatGPT / DeepSeek "对齐"那一步在做的事。搭一个真·迷你 GPT，用 GRPO（DeepSeek 提出，不需要价值网络）教它学会一个可打分的任务。

核心：对同一题生成一组 G 个答案，谁比组内平均分高就强化谁（组相对优势）· loss = −Σ adv·logπ
会看到：组内平均奖励 0.26 → 0.99，模型从乱序数字学会输出 0 1 4 5 7 9 这样的严格递增串 —— 全程没有标准答案。

三、四个例子的"更新公式"其实是一家

它们都长成"新估计 = 旧估计 + 步长 ×（更靠谱的目标 − 旧估计）"，或"把好的行为概率推高"。看一眼就懂它们的亲缘关系。

01 老虎机（增量平均） Q[a] ← Q[a] + (1/N) · ( r − Q[a] ) ——拉一次就把这条臂的估计往实际奖励 r 挪一点
02 Q-learning（TD 更新，多了"状态"和"未来"） Q[s,a] ← Q[s,a] + α · ( r + γ·max Q[s',·] − Q[s,a] ) └────── 更靠谱的目标 ──────┘ ——当下奖励 r 加上"到了新格子 s' 今后还能拿的最好分"，作为新目标
03 REINFORCE（策略梯度，直接调动作概率） loss = − Σ_t log π(a_t | s_t) · G_t ——这局回报 G 高 → 把这局做过的动作概率往上推（梯度上升期望回报）
04 GRPO（策略梯度 + 组内相对优势，不用价值网络） advantage_i = ( r_i − mean(组内) ) / std(组内) loss = − Σ_i advantage_i · log π(答案_i) ——同一题生成一组答案，比平均好的推高、比平均差的压低

看出来了吗：01→02 是给"价值更新"加上了状态和未来（γ）； 02→03 是从"学价值"换成"直接学策略"、并用神经网络； 03→04 是把"动作"换成"生成下一个 token"、把单条回报换成"组内相对优势"。一脉相承。

四、一个真实踩到的坑：奖励被钻空子（reward hacking）

写例子 04 时真实发生的事，比任务本身更值得记住：RL 的难点常常不在算法，而在"奖励怎么定"。

模型总在"钻奖励的空子"，而不是真学会任务

奖励 v1 = "非递减(左≤右)的比例" → 模型输出 4 4 4 4 4 4 全一样！每对都满足≤，轻松满分，却没学会排序。

奖励 v2 = "严格递增(左<右)的比例" → 堵住全相同，但又冒出 1 2 3 8 1 2 3 8 循环，只在断点丢一分照样拿 0.86。

奖励 v3（最终用的）= "从开头连续递增多长" → 断一次就大幅扣分，捷径全失效，模型只能老实从头排到尾。

这就是著名的 reward hacking：你以为在教 A，奖励却被某条捷径 B 骗走了，是 RLHF 最头疼的问题之一。 例子 04 里还用了两个真实 RL 技巧来对付"过早收敛"： 熵奖励（鼓励保持探索，PPO/A3C 标配）和合适的任务难度（让全局最优落在模型够得着的地方）。

五、它和 autoresearch 是同一种循环

理解了这四个例子，再看本项目的"自主研究循环"会清楚很多。

autoresearch 的循环
AI agent 改 train.py 一个旋钮 → 训练 5 分钟 → 看 val_bpb 降没降 → 更好就保留、否则丢弃 → 再来一轮。
奖励信号 = −val_bpb，被优化的是代码。
例子 04 GRPO 的循环
模型生成一组答案 → 奖励函数打分 → 比平均好的强化、差的压低 → 参数更新 → 再来一轮。
奖励信号 = 任务得分，被优化的是模型参数。

一个在调代码、一个在调参数，但都是 "试错 → 打分 → 保留更好的" 这同一种自我迭代。
这正是把"研究"和"学习"统一起来的那个朴素而强大的想法。
