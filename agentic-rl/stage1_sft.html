监督学习(还不是RL) loss masking chat template LoRA

0SFT 在整条后训练线里的位置

SFT 是第一步，也是唯一一步"监督学习"；后面三步才是强化学习。

Base 模型
(会续写不听话) ① SFT
会按指令答 ② DPO
对齐偏好 ③ GRPO
学会推理 ④ 工具RL
学会做事
一句话：SFT 用"指令 → 高质量回答"的成对数据做监督学习，让模型学会"回答的格式与口吻"。 它决定格式下限，但学不会没见过的推理 —— 这正是后面要上 RL 的原因。

1喂什么数据：成对的"问 → 答"

本例故意教一个鲜明风格——简洁中文 + 结尾"喵~"，几步就能肉眼看出 SFT 起效。

# 16 条这样的成对数据(节选)
("地球有几个月亮?",  "地球只有一个月亮，喵~")
("法国的首都是哪?",  "法国的首都是巴黎，喵~")
("鲸鱼是鱼吗?",      "不是，鲸鱼是哺乳动物，喵~")
("企鹅会飞吗?",      "不会，企鹅不会飞，喵~")
为什么用 16 条而不是 3 条？数据太少模型会"死记硬背"那几条然后崩掉； 多给几条同风格的，模型才学到"结尾加喵~"这个模式，能用到没见过的新问题上。

2chat template：把消息套成模型认识的格式

聊天模型不是直接吃纯文本，而是吃带"角色标记"的对话模板。TRL 会自动套。

{"role":"user","content":"月亮绕着什么转?"}        # 你写的
        │  apply_chat_template
        ▼
<|im_start|>user
月亮绕着什么转?<|im_end|>
<|im_start|>assistant          # ← 模型从这里开始"接话"

代码里 add_generation_prompt=True 就是补上最后那行 <|im_start|>assistant，告诉模型"轮到你答了"。

3⭐ loss masking：只在"回答"上算损失

这是阶段1 最该懂的点。你要教的是"怎么回答"，不是"怎么复述问题"。

把整句话切成 token，灰色的问题部分被屏蔽(标 -100)不算 loss，只在绿色的回答部分算：

月亮绕着什么转? 月亮绕着地球转，喵~
问题 prompt — 不算 loss (-100) 回答 completion — 算 loss
代码里用 prompt-completion 格式的数据集，TRL 自动把 prompt 部分置 -100、 只在 completion 上算损失 —— 这就是 loss masking，不需要模板带 {% generation %} 标记。

4LoRA：冻结大模型，只训一小块

为什么本地 Mac 也能微调 5 亿参数的模型？因为我们根本不动那 5 亿。

只有几百万参数

代码：LoraConfig(r=16, target_modules=["q_proj","k_proj","v_proj","o_proj"]) —— 只在注意力的 4 个投影矩阵旁挂小适配器。省显存、快、不易把模型练崩，是本地能跑的关键。

6训练前 → 训练后（实测）

测试题 月亮绕着什么转? 没在 16 条训练集里，能看出风格说明学到的是"模式"不是死记。

训练前 (base)
月亮绕着地球转。
训练后 (SFT)
月亮绕着地球转，喵~
没改一行模型结构，只用 16 条"问→答" + loss masking 训了几步 LoRA， 模型就稳定沾上了"简洁中文 + 喵~"的风格，还泛化到了没见过的问题。这就是 SFT。

7真踩过的坑：小数据 SFT 极易过拟合

这一课最大的雷。同样 16 条数据，超参没调好就翻车。

配置结果训练后输出
8条 / 8轮 / lr 2e-4练崩月亮、（退化成乱码）
16条 / 4轮 / lr 1e-4没学到月亮绕着地球转。（没喵~）
16条 / 6轮 / lr 1.5e-4刚好月亮绕着地球转，喵~
规律：数据越少，学习率和轮数越要小心。太猛 → 把模型概率压垮、输出退化； 太温和 → 风格没学上。SFT/DPO 在小数据上都有这个脾气（DPO 更敏感）。

8SFT 之后呢？

SFT 教会了"格式和口吻"，但它只会模仿见过的答案、学不会新推理，也不知道"两个答案哪个更好"。 于是后训练继续往下走：

① SFT ✓ ② DPO：从"成对偏好"学会"哪个更好" ③ GRPO：用可验证奖励学会"解题" ④ 工具RL：学会"调工具做事"

对应 agentic-rl/ 里的 stage2_dpo.py / stage3_grpo.py / stage4_agentic.py。
