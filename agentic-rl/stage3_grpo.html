RLVR = Reinforcement Learning with Verifiable Rewards：奖励来自规则可验证的信号 （答案对不对 + 格式对不对），不需要训奖励模型。当前最热、岗位最看重的一块。

1⭐ GRPO 的心脏：同题采一组，组内比好坏

这是 GRPO 区别于 PPO 的关键——不用 critic/value 网络，用"同组其他答案的平均分"当基准。

问：17 + 25 = ?　(答案 42)
↓ 同一个 prompt 采样 G=6 个回答
…\boxed{42}+1.3↑
…= 42+1.0↑
…\boxed{42}+1.3↑
…大概是 400.0↓
…等于 410.0↓
…= 42+1.0↑
↓ 组内归一化：advantage = (reward − 组均值) / 组标准差
高于平均的 → 优势为正 → 提高这些回答里每个 token 的概率
低于平均的 → 优势为负 → 压低
为什么省了 critic？PPO 要训一个价值网络来估"基准分"；GRPO 直接用 同组样本的平均分当基准 —— 一组里互相比，省掉一半网络。这正是你在玩具版里学的那行 (r - mean) / std，现在跑在真模型上。

2奖励从哪来：纯规则，可验证

本例任务是简单算术。奖励 = 两条规则之和，一行代码就能判，不需要任何模型。

规则判法奖励
① 正确性\boxed{} 里(或文末)的数字 == 正确答案+1.0
② 格式输出里出现 \boxed{...}+0.3
# TRL 接受一个 reward 函数列表, 自动采样/算组优势/更新
trainer = GRPOTrainer(model, args=cfg, train_dataset=dataset,
                      reward_funcs=[reward_correct, reward_format],  # 两条可验证规则
                      processing_class=tok, peft_config=lora)
# GRPOConfig: num_generations=G(组大小), beta=KL系数(拉住别跑偏), use_vllm=False(Mac)

4GRPO vs PPO vs DPO 一眼对比

要 critic 网络?奖励来源稳定性
PPO要奖励模型复杂
DPO不要成对偏好(离线)易过优化(上一课)
GRPO不要(组内当基准)可验证规则带 KL 约束, 较稳
