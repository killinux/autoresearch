# autoresearch 代码解读

> 本文档解读 Andrej Karpathy 的 **autoresearch** 项目，帮助快速理解整个仓库的设计意图与核心实现。

## 一、项目是什么

autoresearch 是一个让 **AI agent 自主做 LLM 研究实验**的框架。它的核心反转在于：人类不直接改训练代码，而是由 AI agent 在固定时间预算下不断试错、自我迭代。

核心循环：

```
改 train.py → 训练 5 分钟 → 看 val_bpb 是否变好 → 变好就 keep，变差就 git reset → 循环
```

你睡前把 Claude / Codex 指向这个仓库，醒来时会得到一份实验日志和（希望）更好的模型。约 12 个实验/小时，睡一觉能跑约 100 个实验。

### 角色分工

| 文件 | 谁来修改 | 内容 |
|------|---------|------|
| `prepare.py` | **不可改（只读）** | 固定常量、数据下载、BPE 分词器、dataloader、评测指标 |
| `train.py` | **AI agent 修改** | GPT 模型、优化器、训练循环——一切都可调 |
| `program.md` | **人类修改** | agent 的研究指令（一个超轻量的 "skill"） |

### 关键约束

- **固定 5 分钟训练预算**（墙钟时间，不含编译启动）。
- 指标是 **val_bpb**（验证集 bits-per-byte），越低越好。
- 用 bpb 是因为它**与词表大小无关**，这样改架构时能公平比较。

## 二、`train.py` —— agent 的实验场（最核心）

一个**单文件、单 GPU 版的 nanochat**，已经塞进了现代 LLM 训练的多项 SOTA 技巧。

### 1. GPT 模型 (`train.py:32-291`)

不是教科书 GPT-2，而是一个现代化魔改版：

- **归一化**：使用 `rms_norm`，采用 **pre-norm**（`x + attn(norm(x))`）；Q/K 也做 norm（QK-norm，`train.py:91`）。
- **位置编码**：RoPE 旋转位置编码（`apply_rotary_emb`）。
- **注意力**：使用 **Flash Attention 3** 内核（`train.py:20-24`，Hopper 用 varunneal 版本，其他用 kernels-community），支持 **sliding window**。
- **滑动窗口模式**：`WINDOW_PATTERN="SSSL"`（`train.py:195-206`），S=半窗口、L=全窗口交替使用以省算力，最后一层强制全窗口。
- **Value Embedding / ResFormer**（`train.py:83-87`）：部分层把 token 的 value embedding 经由一个输入相关的 gate 混入 attention 的 value，是一种值残差技巧。
- **MLP**：使用 `relu(x).square()`（ReLU²），4 倍扩张。
- **soft-cap logits**（`train.py:282-285`）：`15*tanh(logits/15)` 防止 logits 爆炸。
- **可学习层间标量**（`resid_lambdas`、`x0_lambdas`，`train.py:277`）：每层学习混入多少原始 embedding（x0 残差）。
- **特殊初始化**（`init_weights`）：多数投影矩阵零初始化，embedding 转 bf16。

### 2. 优化器 `MuonAdamW` (`train.py:297-426`)

混合优化器，nanochat 的精髓：

- **2D 矩阵参数（transformer 主体）用 Muon**：通过 **Newton-Schulz / Polar Express 迭代**（`train.py:323-336`）把梯度做**正交化**，再加 **NorMuon 方差归约**和 cautious weight decay。
- **其余参数（embedding、lm_head、标量）用 AdamW**。
- 用 `@torch.compile` 融合更新步，并用 0 维 CPU tensor 传超参以避免重编译（`train.py:361`）。

### 3. 超参与调度 (`train.py:429-532`)

顶部的大写常量是 agent 主要调的旋钮：

- `DEPTH`：模型层数，主复杂度开关。
- 各种学习率：`EMBEDDING_LR` / `UNEMBEDDING_LR` / `MATRIX_LR` / `SCALAR_LR`。
- `TOTAL_BATCH_SIZE`、`DEVICE_BATCH_SIZE`、`WINDOW_PATTERN` 等。

学习率按 `1/√d_model` 缩放；调度是 warmup → 恒定 → warmdown，全部基于 `progress = 已训练时间 / TIME_BUDGET`。

### 4. 训练循环 (`train.py:543-604`)

- **梯度累积**：凑够 `TOTAL_BATCH_SIZE`（约 524K tokens/步）。
- **按时间停**而非按步数停（`train.py:603`）：跑满 5 分钟就退出，且 `step>10` 后才计时（排除编译预热）。
- **快速失败**（`train.py:570`）：loss 为 NaN 或 >100 直接 `exit(1)`。
- **关闭 Python GC**（`train.py:593-596`）：避免 ~500ms 卡顿。
- 实时打印 loss、MFU（算力利用率）、tok/sec、剩余时间。

最后用 `evaluate_bpb` 算验证指标，打印结构化 summary（agent 要 grep 的输出）。

## 三、`prepare.py` —— 固定的"裁判"（只读）

- **数据**（`prepare.py:41`）：从 HuggingFace 的 `karpathy/climbmix-400b-shuffle` 下载 parquet 分片，**最后一片（shard_06542）固定作验证集**，其余作训练。
- **分词器**：用 `rustbpe` 训练 8192 词表的 BPE，存成 tiktoken 格式。
- **dataloader**（`make_dataloader`，`prepare.py:276-337`）：**BOS 对齐 + best-fit 装箱**——每行以 BOS 开头，贪心填入"最大能放下的文档"，放不下时裁切最短文档填满，**100% 利用率、无 padding**。
- **`evaluate_bpb`**（`prepare.py:343-365`）：**不可改的真值指标**。把每 token 的交叉熵（nats）按目标字节数加权求和，转成 bits/byte，特殊 token（0 字节）排除。固定用 `MAX_SEQ_LEN` 保证跨配置可比。

固定常量（`prepare.py:30-32`）：

- `MAX_SEQ_LEN = 2048`（上下文长度）
- `TIME_BUDGET = 300`（5 分钟训练预算）
- `EVAL_TOKENS = 40 * 524288`（验证 token 数）

## 四、`program.md` —— 给 agent 的"研究协议"

定义 agent 的完整工作流：

1. 建分支 `autoresearch/<tag>`
2. 第一次跑 baseline（原样运行）
3. 进入**永久循环**：改代码 → commit → `uv run train.py > run.log` → grep 出 `val_bpb` → 好就保留并推进分支，差就 `git reset` → 记录到 `results.tsv`

关键约束：

- **简洁性准则**：同等效果下更简单更好；删代码还能持平/更好是最佳结果。
- **永不停止**：循环开始后绝不问人类"要继续吗"——人类可能在睡觉，要一直跑到被手动打断。
- **崩溃处理**：低级 bug 就修，思路本身有问题就记 `crash` 跳过。

`results.tsv` 格式（制表符分隔）：

```
commit	val_bpb	memory_gb	status	description
a1b2c3d	0.997900	44.0	keep	baseline
b2c3d4e	0.993200	44.2	keep	increase LR to 0.04
c3d4e5f	1.005000	44.0	discard	switch to GeLU activation
d4e5f6g	0.000000	0.0	crash	double model width (OOM)
```

## 五、一句话总结

这个仓库**不是一个普通的训练脚本，而是一个"自主研究的实验台"**：`train.py` 是一个已相当先进的 nanochat 小模型训练器（Muon 优化器 + FA3 + 滑动窗口 + ResFormer 等），但它真正的用途是被 AI agent 当作"可优化的对象"，在固定 5 分钟预算下不断试错，目标只有一个——**把 val_bpb 压到最低**。
